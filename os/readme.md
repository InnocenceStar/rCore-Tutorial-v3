## trap

trap本质上是一种分发机制. trap 是总入口，scause 是分拣员。 CPU 不管你是主动敲门还是被动被踢进来的，统一先 trap 到内核，然后读 scause 判断"你是谁"，再分发到对应的处理函数。

在 RISC-V 中，不管是系统调用、外部中断还是异常，CPU 都会"陷入"（trap）到同一个地方处理。

| 类型     | 触发方式                       | scause 值（示例）                                |
| -------- | ------------------------------ | ------------------------------------------------ |
| 系统调用 | 用户执行 `ecall`               | 8（Environment Call from U-mode）                |
| 外部中断 | 硬件设备发信号（时钟、键盘等） | 最高位为 1，如 5（Supervisor Timer Interrupt）   |
| 异常     | CPU 执行中出错（缺页、除零等） | 如 13（Load Page Fault）、15（Store Page Fault） |

流程:

```
ecall / 硬件中断 / 异常
        │
        ▼
  CPU 自动跳转到 stvec 指向的地址
        │
        ▼
  trap_handler()          ← 统一入口
        │
        ▼
  读 scause 寄存器
        │
        ├── scause == 8        → sys_call()    系统调用
        ├── scause 最高位 == 1  → irq_handler() 外部中断
        └── 其他               → exception()   异常处理
```

> 在 RISC-V 架构中，跳转到“跳板代码”（即 Trap Handler 入口）的过程完全由硬件自动完成，其核心机制依赖于一个关键的控制状态寄存器——stvec（Supervisor Trap Vector Base Address Register）。
> 这个寄存器存储了内核预先设置好的 trap 处理程序的起始地址。
> 当任何 trap 事件（系统调用、中断、异常）发生时，CPU 会自动将程序计数器（PC）设置为 stvec 的值，从而无条件跳转到该地址执行代码。

## pte & pt

```
PageTable（页表管理器）
│
│  持有一个 root_ppn（根页表的物理页号）
│
├── 根页表（物理页，包含 512 个 PTE）
│     ├── PTE[0]  → 指向第二级页表 或 存映射
│     ├── PTE[1]  → ...
│     └── PTE[511]
│
├── 第二级页表（物理页，包含 512 个 PTE）
│     ├── PTE[0]  → 指向第三级页表 或 存映射
│     └── ...
│
└── 第三级页表（物理页，包含 512 个 PTE）
      ├── PTE[0]  → 存最终映射（VPN → PPN）
      └── ...
```

## 地址空间

在 Sv39 中，合法的虚拟地址只有两种：

- 高 25 位全为 0（用户空间）
- 高 25 位全为 1（内核空间）

## 分页

### satp

- [63:60] : MODE, 分页模式；
- [59:44] : ASID, 地址空间标志符，用于区分不同进程的页表缓存（TLB），通常为0；
- [43:0] : PPN, 页表基地址的物理页号；

### tips

- 页表是由寄存器satp控制开启和关闭的，开启后访问的内存地址都是虚拟地址，但是内核采用的是恒等映射；

1. 开启前（物理地址阶段）： 此时 CPU 还没开分页，代码里写的地址就是物理地址。汇编代码通常会先建立一个临时的页表，把内核所在的物理内存区域做成恒等映射。
2. 开启瞬间（sfence.vma + 写 satp）： 此时 CPU 立即切换到虚拟地址模式。
3. 开启后（虚拟地址阶段）：
   - 如果之前的映射做得好（恒等映射），那么 PC 指针指向的下一条指令的物理地址没变，虚拟地址也没变，CPU 就能顺利取指继续运行。
   - 关键点： 此时虽然代码逻辑没变，但底层的寻址方式已经彻底变了。之后所有的 HEAP_SPACE 访问，虽然看起来地址没变，但实际上都已经经过了 MMU 的翻译。

## trap & 任务切换

|          | Trap                            | 任务切换                         |
| -------- | ------------------------------- | -------------------------------- |
| 本质     | 特权级切换（用户态 → 内核态）   | 进程/线程切换（内核态 → 内核态） |
| 谁在执行 | 用户程序触发，CPU 陷入内核      | 内核调度器主动执行               |
| 地址空间 | 需要切换（用户空间 → 内核空间） | 不需要切换（全程在内核空间）     |
| 典型场景 | 系统调用、缺页异常、中断        | 时间片用完、进程阻塞、优先级调度 |

## device tree

QEMU 启动
↓
RustSBI（运行在 M-mode）

1. 加载设备树（DTB）到内存
2. 设置 a0 = hart_id（当前硬件线程编号）
3. 设置 a1 = DTB 的物理地址
4. 跳转到内核入口地址（entry.S）
   ↓
   entry.S（运行在 S-mode）
5. 接收 a0、a1（直接使用，不重新设置）
6. 设置栈指针 sp
7. 调用 rust_main(a0, a1)
   ↓
   rust_main(\_hart_id, dtb_pa)
8. 将 dtb_pa（物理地址）转为虚拟地址
9. 调用 device_tree::init(dtb_va)
